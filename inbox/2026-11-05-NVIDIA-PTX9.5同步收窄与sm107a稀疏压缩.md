# PTX 9.4/9.5：同步语义从「整个 proxy」收窄到「read 子集」，sm_107a 把 2:4 稀疏做成指令
- 来源: https://docs.nvidia.com/cuda/parallel-thread-execution/ （§13.1/13.2 Release Notes）
- 日期: PTX 9.4 随 CUDA 13.4.1 发布（2026-09-09）；9.5 条目已在线但尚无对应 CUDA 发布说明
- 标签: #NVIDIA #PTX #TMA #tcgen05 #稀疏

## 摘要
PTX 9.4 新增 `sm_107` / `sm_107f` / `sm_107a` 三个目标（f=家族特性、a=架构特性），并把 TMA/tcgen05 的同步粒度、稀疏压缩、TMA 描述符分配类都往下压了一层；9.5 草案继续这个方向，新增 alias fence、按 proxy 定向的 `wait_group`、以及 `%locality_domain_id` 等特殊寄存器。

## 要点
- 9.4 同步：`.multicast::cluster::32b` 扩展到 `mbarrier.arrive/expect_tx/complete_tx`、`cp.async.bulk(.tensor)`、`tcgen05.commit`；`tcgen05.commit` 新增 `.sync_restrict::shared::read::mma::a`——只等 MMA 对 SMEM 的**读**完成，不再等整条流水
- 9.4 稀疏：新增 `spcompress` / `spdecompress`（dense→2:4 结构化稀疏 + 元数据，`.elemsize`=b8/b16、`.idxsize`=b2/b4）与 `tcgen05.ld{.red}.spcompress`，仅 `sm_107a`——稀疏从 Tensor Core 内部特性变成 ISA 级数据搬运原语
- 9.4 TMA 周边：`cp.async.bulk.prefetch(.tensor)` 加 `.level::eviction_priority`；新增 `applypriority.async.bulk(.tensor)`；`cp.async.bulk.tensor` 加 `.override::global_address` 与 `.im2col_no_offs::w`
- 9.5（文档先行）：`cp.async.bulk.wait_group.sync_restrict::proxy::async`、`fence.alias.sync_restrict::read.release.sys`、`fabric.submit.commit_group` + `fabric.wait.sync_restrict::read`（`::reads` 废弃）、`tensormap.replace .alloc_class` + `tensormap.query.alloc_class_large`
- 9.5 新概念 **locality domain**：`%locality_domain_id`、`%locality_domain_supplemental_sm`；vLLM 2026-10-09 博客已用它按域切分 MoE 权重（Rubin NVL72 自报 7.8× GB200）
- 读法：fence 从「全体读/整 proxy」细化到 read 子集与 proxy 定向，说明异步代理域的对齐成本已经能被编译器算账；写 kernel 时按此重排 `mbarrier` / commit 的等待范围即可省同步开销，但**全部依赖 sm_107a 与 9.5 工具链**
- 口径：条目取自 PTX 在线文档原文；sm_107 与 Rubin 的对应关系文档未明说，CUTLASS 最新为 4.8.1（2026-10-15），是否已封装这些原语未核
