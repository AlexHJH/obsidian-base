## 固定规范与当前状态

1. **官方 IME 不是 SpacemiT 的同名厂商扩展。** 以下 IME 指 RISC-V IME TG 的 **Zvvm family**。相同“Integrated Matrix Extension”英文名称不构成编码、几何、数值语义或二进制兼容证据。
2. **IME 的当前固定阅读基准是 2026-08-24 的 v0.9.0 ARC Review Candidate**，commit `5a2d0f65ef19f8c876ac71c4a496c6f98b5422ad`，文件 `src/unpriv/integrated-matrix.adoc`。release 明说 pre-release draft、not ratified、not official RISC-V release。它为 ARC 评审取代原 `integrated-matrix/v0.9-freeze-20260804` 快照，不能写“IME 已 ratify”。[release](https://github.com/riscv/integrated-matrix-extension/releases/tag/v0.9.0)；[固定规范正文](https://github.com/riscv/integrated-matrix-extension/blob/5a2d0f65ef19f8c876ac71c4a496c6f98b5422ad/src/unpriv/integrated-matrix.adoc)。
3. **IME main 不是上述最新候选。** 本次读取 main 为 `6effbcae3204e5a8a9c9d15ff53959918144870c`，正文仍在 `src/integrated-matrix.adoc`；review tag/branch 已使用重整后的路径。不要用 main 链接佐证 v0.9.0 的修订细节。[main 固定快照](https://github.com/riscv/integrated-matrix-extension/blob/6effbcae3204e5a8a9c9d15ff53959918144870c/src/integrated-matrix.adoc)。
4. **VME 的规范正文不在 riscv/riscv-vme main。** 该仓库本次 head `5570c7b2b8e2d5b28b3627a0bbed57bf3afb4e6a` 的 `src/unpriv/matrix.adoc` 仍只是 placeholder，其 2026-07 两个 release 不能证明发布了 VME 规范。真正规范是 ISA manual 的 [PR #2997](https://github.com/riscv/riscv-isa-manual/pull/2997)，仍 open，head `31a76665e9fc532199c21b99f1311bc8345bc532`，文件 `src/unpriv/zvt.adoc`，标题 **Zvt Family of Vector Matrix Extensions, Version 0.4**。[固定正文](https://github.com/riscv/riscv-isa-manual/blob/31a76665e9fc532199c21b99f1311bc8345bc532/src/unpriv/zvt.adoc)。

### 历史方案对照：仅作演化背景

2025-04-07 的作者幻灯片可帮助理解为何后来收敛，但**不是当前编码规范**：

- **Option A**（Marc Casas / Erich Focht）把 tile shape 放在32位元数据里，包含 rows、cols、SEW、dtype、mtype，用类似二维 vsetvl 的 shape discovery，再 load/multiply/store，M/N/K 都参与 strip mining。重点是软件与实现协商可支持的 tile，而不是固定一种尺寸。[作者原稿](https://lf-riscv.atlassian.net/wiki/download/attachments/46071957/Option%20A.pdf?api=v2)
- **Option C**（会议归属 Jose Moreira）把数据解释为 l 个 λ×λ 小矩阵，L=lλ²；L=16 时列出16个1×1、4个2×2或1个4×4的例子。其“相同 binary 在不同 λ/L 上取得同样结果”是此历史提案作者的设计主张，**不能转移成 v0.9.0 的跨实现 bit-exact 承诺**，后者有公开的 implementation-defined reduction tuple。[作者原稿](https://lf-riscv.atlassian.net/wiki/download/attachments/46071957/Option%20C.pdf?api=v2)
- **Option G**（Erich Focht，基于与 Marc Casas 的 Proposal A，Philipp Tomsich 参与）显式使用 RMUL/CMUL 描述二维寄存器组映射，主张 A/B/C 灵活占用多个 vector registers、支持内积和外积；报告指出 IME charter 不允许暴露独立 accumulator，因此讨论通过 register renaming / reservation stations 隐藏累加器。原稿 `vmts` 是 GET shape、`vmmset` 是配置，**这些早期助记符与当前 `vmts` tile store 等不能混用**。性能百分比是作者提案论证，不是本次验证过的实测结果。[作者原稿](https://lf-riscv.atlassian.net/wiki/download/attachments/46071957/Option%20G.pdf?api=v2)

因此，把2025年的“动态二维shape/两个寄存器乘数”直接解释成2026年的 λ、LMUL、EMUL_C 是错误的；应展示方案收敛与参数简化过程，而不是将历史草案和候选规范合成不存在的超级 ISA。

## 未纳入主结论的材料与边界

- MTE 的论文题名为 A geometry-agnostic matrix-multiplication instruction Set Architecture extension，DOI 10.1016/j.future.2026.108766。出版商正式卷期显示 2027-03，首次在线日期未从可访问一手全文确认，因此不计入日期已核实的两年窗口主条目，也不引用其摘要数字作为硅上性能。[出版社摘要](https://www.sciencedirect.com/science/article/pii/S0167739X26004000)
- Ara、Gemmini 的原始研究早于本时间窗。Gemmini 通过窗口内 Virgo 研究纳入，而不是将原始工作重新记成近两年成果。
- AME ratification plan 的未来日期仍是目标；过了某个计划日期也不自动证明里程碑完成。[官方计划](https://riscv.atlassian.net/wiki/spaces/AMEX/pages/55083420/Ratification+Plan)
- 会议议程、AI-generated minutes、open issue、作者提案和正式投票的证据等级不同。议程只能证明安排讨论某项，不能凭它推导正式决议；空会议模板不算新进展。
- PR merged、release 分支包含、发行版二进制可用、完整代码生成和硬件验证分开记录。本轮未自行构建工具链、运行模拟/硬件测试或进行 ISA 一致性认证。
- 对未定位到的上游支持只标“本次未确认”；可能有未索引、改名或另分支材料。本档案不是两年所有邮件和论文的穷尽目录。
- 全文数值算例是明确假设下的推导；厂商峰值、作者实测、功能模拟和 PPA 研究均保留原口径，不相互替代。
