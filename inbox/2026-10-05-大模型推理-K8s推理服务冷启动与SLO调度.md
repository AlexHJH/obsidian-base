# K8s 上的 LLM 服务 2026：冷启动 2–10 分钟让响应式扩缩结构性迟到
- 来源: https://dev.to/avneet_bansal_a65b3f31fc4/llm-serving-on-kubernetes-in-2026-whats-solved-and-whats-still-open-52ad
- 日期: 2026（引 arXiv 2607.16596 / 2608.06557 / 2609.20874）
- 标签: #大模型推理 #推理部署 #Kubernetes #SLO调度

## 摘要
一篇 2026 产业综述把「K8s 跑 LLM」拆成已解与未解：真正卡住的是模型分发冷启动与扩缩的时机错配。经验研究（arXiv 2607.16596）在 1B/7B/70B 权重上比较 modelcar sidecar、原生 image volume、对象存储下载三条分发路径，得出启动要 2–10 分钟；配套论文（2609.20874）据此判定响应式扩缩「结构性地总是晚一步」。

## 要点
- 缺失的原语是「一等公民的模型/权重分发」，靠 sidecar 与镜像层拼凑 → 冷启动长到让 autoscaling 失去意义
- 扩缩信号在进化：从队列深度 / KV cache 利用率 → Cascade（arXiv 2608.06557）证明同一 SLO 下短对话与长 agentic 推理的紧迫度差异巨大，可把排队与数据搬运开销导向「扛得住」的请求
- 生态面：Gateway API Inference Extension、NVIDIA Dynamo、ModelExpress 权重分发、KAI Scheduler / Grove / Kueue
- agentic 负载把问题放大：重复交互与长轨迹使 prefill 成本与提速需求同时上升
