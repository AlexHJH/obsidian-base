# Xcode 26.5 编出的 mlx.metallib 会让 M5 NAX 内核吐乱码
- 来源: https://github.com/ml-explore/mlx/issues/3586
- 日期: 2026-09-14
- 标签: #MLX #AppleSilicon #Metal #工具链 #M5

## 摘要
用 Xcode 26.5 / metalfe-32023.883 从源码构建 `mlx.metallib` 后，跑 MiniCPM-V-4.6-8bit 直接输出乱码（"yes111111111"）；换回 PyPI 的 mlx-metal 即恢复正常。定位为 Metal 编译器回归或 MLX 内核依赖了编译器行为差异，与 Python 侧改动无关。

## 要点
- 严格交叉验证：PyPI mlx + 本地 metallib → 乱码；本地 mlx + PyPI mlx-metal → 正常，问题跟着 shader 库走
- 版本线索：PyPI 0.31.2 后端用 SDK 26.4 构建，本地用 Xcode 26.5 / SDK 26.5
- 工程建议：M5 上不要自行构建 metallib（尤其 NAX GEMM 路径），锁定官方 wheel；自建版本必须与官方量化模型输出对拍
