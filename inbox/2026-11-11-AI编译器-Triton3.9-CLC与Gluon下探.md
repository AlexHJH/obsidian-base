# Triton 3.9.0：CLC 把普通 kernel 变成 persistent loop，Gluon 下探到 inline asm 与 cache policy
- 来源: https://github.com/triton-lang/triton/releases/tag/v3.9.0
- 日期: 2026-10-27（release notes 全文阅读）
- 标签: #Triton #MLIR #GPU编译 #Blackwell #Gluon

## 摘要
3.9 的主线是「少写硬件特定代码也能拿到硬件控制」：`clc=True` 让 one-tile-per-program 的 kernel 在 SM100+ 上自动变成 Cluster Launch Control 持久循环（含 `warp_specialize=True`），而 Gluon 侧新增每线程 `gl.inline_asm`（可带 shared/tensor memory 描述符）与 `cache_policy`（L1/L2 策略、fractional eviction、L2 prefetch 大小）。同时 barrier 插入被重写成独立 pass，把「补漏 + 去冗余」从散落的 pattern 收进一处。

## 要点
- 语义收紧：`acquire/release/acq_rel` 原子现在会插 CTA 宽 barrier；RMW 与 CAS 默认 `acq_rel`，要绕过须显式 `sem="relaxed"` —— 老 kernel 性能可能因此变，先查原子热路径
- 已修的都是「编译器自己搬错数据」类 bug：pipeline 多 stage 共用累加器的 Blackwell MMA、混合 packing 的 FP4 MMA、TMEM 在释放后被复用、TMEM 分配器被覆盖、unaligned TMA 的 per-stage 缓冲
- 行为变更（会改结果）：E8M0 `0x00` 解码从 0 改为 `2^-127`、`0xFF` 从 inf 改为 NaN；影响用块缩放（mxfp）且踩到边界值的 kernel
- NVIDIA 后端：TCGen5 MMA 在 N tile 间复用 A operand；SM103 上 FP4×FP4 快 6–15%；Gluon kernel 可用 256-bit 全局访存；sm_90+ 换用捆绑的 CUDA 13.4.59 ptxas
- 判读：`clc=True` 的意义是把「持久化 + 任务分发」从手写变成编译选项，与 [[NVIDIA-Tensor-Core-TMA与AI指令体系]] 里的 TMA/mbarrier 手工管线是两条并行的降低门槛路线
