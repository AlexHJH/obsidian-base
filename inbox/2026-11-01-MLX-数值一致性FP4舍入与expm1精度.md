# MLX 两处数值一致性缺口：FP4 舍入 CPU/Metal 不一致、Metal expm1 少一项补偿
- 来源: https://github.com/ml-explore/mlx/issues/4753 ｜ https://github.com/ml-explore/mlx/issues/4765
- 日期: 2026-10-23 / 2026-10-25
- 标签: #MLX #量化 #数值精度 #确定性

## 摘要
两个独立 issue 指向同一类问题：同一模型在 GPU 与 CPU 上数值不同。FP4 量化在 CPU 上部分 ties 朝零舍入、Metal 一律 ties-to-even；Metal `expm1` 的参数归约只减了 ln2 的高位，漏掉 `-1.42860677e-6` 这段补偿，误差一路传到 `erf` 与精确 GELU。

## 要点
- FP4（mlx 0.32.4，M5 Pro）：0.75→0.5（应 1）、1.75→1.5（应 2）、3.5→3（应 4）；而 0.25/1.25/2.5/5 又舍对了 → CPU 实现自身不自洽，非有意设计
- OCP MX 规范只强制「至少支持 ties-to-even」，所以 Metal 那侧是合规基准，CPU 侧是 bug
- expm1（0.32.2 实测 ulp 对 float64）：[3,10) 最大 335.9 ulp、[1,3) 102.3 ulp；CPU 侧 3.4 ulp。补上低位后 [−10,10] 降到 0.98 ulp
- 传染面：`erf` 在 |x|>0.9277 调 expm1，exact GELU 误差 4.3e-7 → 2.6e-7；`main` 分支同源未修
- 相关第三条：nvfp4 的 CPU `qqmm` 忽略 `global_scale_x/global_scale_w`（#4800，10-30）→ CPU 参考路径不能当 golden
- 读法：跨后端一致性要按「算子级 ulp + ties 规则」验，端到端 loss 对比会把这些差异平均掉
