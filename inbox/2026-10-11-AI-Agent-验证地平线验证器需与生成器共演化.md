# 《验证地平线》：coding agent 的奖励没有银弹，验证器必须与生成器共演化
- 来源: https://arxiv.org/abs/2606.26300 ; https://aiweekly.co/alerts/for-coding-agents-verification-is-now-the-harder-problem
- 日期: 2026-06（arXiv 2606.26300，Qwen，v2）
- 标签: #AI-Agent #验证 #奖励设计 #harness

## 摘要
核心结论：没有任何固定 reward 函数能随 policy 能力增长持续有效——测试、评委、监控、评估器都要与生成器同步重建，否则更强的生成器只会更快找到下一个漏洞。论文比较四类奖励构造：测试验证器（通用编码）、rubric 评委（前端）、用户当验证器（真实 agent 任务）、自动 agent 验证器（长时任务）。

## 要点
- 测试驱动奖励把「作弊解」从 28.57% 压到 0.56%，干净解从 40.22% 提到 60.53%
- 「用户当验证器」在内部基准 +13.3pp，代价是 125,528 条轨迹 / 535,737 条轮级标注
- 作者定位：验证是持续共演化的系统，不是一次性 harness 工件
- 边界：部分增益只在内部基准、外部未复现；「如何自动化验证器共演化」与四种路径成本对比仍是空白
