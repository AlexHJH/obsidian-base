# MLX 长上下文推理：mlx-lm 新特性与「decode 速度」基准陷阱
- 来源: https://medium.com/@michael.hannecke/choosing-an-on-device-llm-runtime-on-apple-silicon-a-decision-framework-beyond-benchmarks-2449067b8b67
- 日期: 2026-09-02
- 标签: #MLX #Apple-Silicon #长上下文 #基准评测

## 摘要
mlx-lm 为长 prompt 补齐旋转固定大小 KV Cache、prompt caching 与可配置 prefill 步长；但社区实测揭示「decode 吞吐」基准的陷阱——长上下文下 MLX 含 prefill 的有效吞吐可能远低于标称。

## 要点
- mlx-lm 长 prompt 三件套：旋转 KV cache（近似无限上下文）、prompt caching、`--prefill-step-size`（默认 2048）控峰值显存
- Groundy 实测：M1 Max 8.5K token 上下文，含 prefill 的有效吞吐仅 ~3 tok/s（decode 单独报 51 tok/s），llama.cpp 总耗时反而更快
- 结论：长上下文选型看「总耗时」而非 decode 速度，context-free 基准会误导
