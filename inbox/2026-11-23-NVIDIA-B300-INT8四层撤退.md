# B300 的 INT8 是"纸面存在"：四层栈一致撤退，PTX、CUTLASS、vLLM、SGLang 全没给
- 来源: https://arxiv.org/abs/2608.11693
- 日期: 2026-08-12 (v1) / 2026-08-14 (v2)
- 标签: #NVIDIA #Blackwell #INT8 #量化 #CUTLASS #vLLM

## 摘要
B300（sm_103a）的官方规格把 FP8:INT8 的稠密算力比写成约 30:1（H200/B200 都是 1:1）。这篇 8 页审计沿"规格书 → PTX ISA → CUTLASS → vLLM/SGLang"四层追 INT8 W8A8 的实际可用性，结论是四层各自独立地、但方向一致地把 INT8 撤掉了：标称存在的格式默认不可部署。

## 要点
- PTX 层：同一版 PTX 把 FP4 kinds 扩到 sm_103a，却始终没给第五代整数路径（`tcgen05.mma.kind::i8`）开 sm_103a → B300 上唯一架构合法的整数张量核路径退回 warp 级 legacy IMMA
- 版本谱系（表格法很好用）：`tcgen05.mma` 基础变体 8.6/sm_100a → 8.8/sm_100f → 9.0/sm_110f；`.kind::i8` 硬卡在 8.6/sm_100a 与 9.0/sm_110a；`.kind::mxf4nvf4` 才扩到 sm_103a。**SM100 与 SM103 必须分开看，"Blackwell 支持" 对 B200 真、对 B300 假**
- CUTLASS 层：kernel generator 对任何 103a target 显式跳过 INT8 UMMA 生成，而 FP8 无条件生成
- 服务层：vLLM 没有 Blackwell 的 INT8 GEMM，模型加载完成后第一个 forward 才硬报错（naive 测试成本高）；SGLang 的 AOT INT8 GEMM 停在 Sm90，其 FP8 调优配置已覆盖 B200
- 逃生口：给 vLLM 的 INT8 路径改走 JIT 编译的 Triton 后端（环境变量开关）；另指出 profiler 判据的假阴性陷阱——sm_103 上没有 tcgen05 整数 kind 可供 kernel 使用，靠 grep tcgen05 会误判成回退实现，应看 IMMA 指令
- 判读：量化格式的可用性是整条栈的属性，不是模型权重或规格书的属性；本文无性能测量（配套测量研究另发），但版本表 + commit 钉死的方式可直接搬去做自研芯片的"特性真伪审计"模板
