# Agent 沙箱层从「功能」变成「基础设施选型」：微虚拟机成事实默认

- 来源: https://www.langchain.com/blog/langsmith-sandboxes-generally-available ，https://www.taskade.com/blog/ai-agent-sandboxes ，https://shattered.io/gke-agent-sandbox-gvisor-300-per-second-2026
- 日期: 2026-05-13（LangSmith GA）／2026-11-18 前后二手汇总再度热传，注意别把汇总日当发布日
- 标签: #AI-Agent #Sandbox #microVM #LongLoop

## 摘要
Agent 代码执行环境正从「容器 + 命名空间」升级为硬件虚拟化 microVM，并把密钥注入、快照分叉、按需暂停做成平台原语。LangSmith Sandboxes 5/13 GA 是这条线的标志：内核级隔离 + Auth Proxy + copy-on-write 分叉，同期 Google GKE Agent Sandbox（gVisor）已按每秒数百个沙箱的规模供货。

## 要点
- 隔离档位：microVM（LangSmith/Firecracker 系、Fly Sprites、CodeSandbox）> gVisor（GKE Agent Sandbox）> 容器；LangSmith 的口径是容器挡不住供应链投毒与内核提权（引 Shai-Hulud npm 蠕虫、Copy Fail CVE）
- 平台原语比隔离技术更决定可用性：snapshots + 廉价 COW fork（并行分支）、blueprint 预热、Service URL、creator-private、可暂停；冷启动据二手报道 p50 <1s
- 密钥统一走出口代理（Auth Proxy / Vercel / Daytona / Anthropic vault-proxy）：沙箱只见占位符，真实凭据在网络层注入 + 域白名单
- 规模化数字（均为厂商或二手口径，未复核）：GKE 单集群最高 300 沙箱/秒、GA 后 5 个月用量涨 16×；Modal 自称 1 分钟可建 100 万沙箱、支持百万并发
- 选型判据：先看「谁管生命周期 + 凭据在哪一侧」，再看隔离等级；把沙箱当「跑得动代码的容器」是最常见的低估
- 对本库主线：LongLoop Console 的验证检疫需要的是可快照、可分叉、凭据不进运行时的执行面，而非更快的沙箱
