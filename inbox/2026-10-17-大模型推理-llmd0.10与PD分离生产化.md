# llm-d 0.10：PD 分离服务的生产化收口（底座绑 vLLM 0.30）
- 来源: https://llm-d.ai/ ; https://llm-d.ai/docs/architecture/advanced/disaggregation ; https://github.com/vllm-project/vllm/releases
- 日期: 2026-10（0.10 发布）；vLLM 0.30.0 于 2026-09-22
- 标签: #大模型推理 #PD分离 #vLLM #Kubernetes

## 摘要
Kubernetes 原生推理栈 llm-d 发布 0.10，主题从「加功能」转为「可运维」：签名发布镜像、更安全的 rollout，并给每条 well-lit path（含 1P1D 分离路径）发布测试矩阵，底座绑定 vLLM 0.30。PD 分离（prefill 算力密集 / decode 带宽密集分池）已成默认服务形态，官方口径 3× 输出吞吐、2× TTFT，并强调 GPU/TPU/XPU/CPU/NPU 的可移植性。

## 要点
- 分离落地件：prefill pod 池 + decode pod 池共用一个 InferencePool，靠标签 `llm-d.ai/role`（prefill / decode / prefill-decode）路由；P/D 可用不同 TP 度 —— decode 吃带宽需要更大 TP，prefill 用小 TP 更省
- KV 接线是成熟度标志：vLLM 原生 `OffloadingConnector` 把被驱逐的 KV 块卸到 host CPU（`CPUOffloadingSpec`）或共享文件系统，另有 LMCacheConnector / MooncakeConnector 做跨 pod P2P KV 传输与远程 KV 池
- MoE 走宽专家并行：data-parallel attention + `--enable-expert-parallel`，跨 LeaderWorkerSet / DisaggregatedSet，用 DeepEP 或 PPLX 做跨 rank token dispatch/combine
- 参照系：PD 分离由 DistServe（OSDI 2024）形式化，论文口径比 colocated 服务多 7.4× 请求或 12.6× SLO 达成率；Perplexity / Meta / LinkedIn / Mistral 已在生产运行，NVIDIA Dynamo 以它为核心能力
