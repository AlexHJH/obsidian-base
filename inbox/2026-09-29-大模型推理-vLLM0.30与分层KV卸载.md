# vLLM 0.30.0：KV cache 分层卸载上游原生化，布局重构收敛后端差异

## 摘要
vLLM 9/10 博客说明原生分层 KV 卸载（v0.22 起内置、无外部依赖）的设计，9/22 发布 0.30.0；同期 KV cache 布局做了一次重构——把 K/V 打包进 content 维（backend-published KV packing），并支持按 KV-cache group 选择不同 attention 后端。

## 要点
- 核心设计是 host-centric：所有 KV 数据都经 CPU DRAM，host 侧用规范化布局（每页存一层的一块、跨 TP rank 的 KV head 聚成连续区），于是不同加速器、不同注意力后端、不同并行配置都能共享同一份 KV
- 二级层带来跨节点能力：缓存水平扩展、新实例用共享存储热启动、PD 分离或负载均衡时对等传输 KV
- 混合模型处理：Mamba 状态层每 chunk 覆盖的 token 远多于全注意力层，因此卸载频率更低——与 SGLang 的 UnifiedRadix/HiCache 方向同构
- 调度侧同期改动（发布流）：KV-cache watermark 降抢占、two-phase allocation 处理跨组前缀命中、Marconi 式混合缓存准入、Mamba/线性注意力的前缀缓存保留、LIFO 空闲块复用顺序修复 → KV 管理从「一个池子」变成有策略的分层资源
- 读法：引擎竞争已从「谁的 attention 快」转到「谁能把 KV 的放置、共享与生命周期管明白」
