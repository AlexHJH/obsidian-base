# OSDI'26 GPU 编译器与内核专场：mega-kernel、CUDA Graph、虚拟张量
- 来源: https://www.usenix.org/conference/osdi26/technical-sessions
- 日期: 2026-09-17
- 标签: #AI编译器 #OSDI #Triton #megakernel

## 摘要
OSDI'26「GPU Compilers and Kernels」场次四篇指向同一方向：把算子级的 kernel-per-operator 执行模型整体替换掉——要么合成单个持久 mega-kernel，要么消除数据搬运，要么接管运行时调度。

## 要点
- **Twill**（Stanford + NVIDIA，即 *Optimal Software Pipelining and Warp Specialization for Tensor Core GPUs*）：把 SWP 与 WS 的组合调度建成联合优化问题交给约束求解器，heuristic-free、可扩展到新架构、保证最优；能重新发现并由此**证明** FlashAttention 在 Hopper/Blackwell 上专家手写调度的最优性——与 Triton autoWS 的启发式路线形成对照
- **MPK / Mirage Persistent Kernel**（CMU 陈天奇/贾志豪 + 清华 + NVIDIA + PKU）：首个把多 GPU 模型推理自动编译成单个 mega-kernel 的编译器+运行时；引入 SM 级图表示，在单个 SM 粒度捕获数据依赖，从而支持跨算子软件流水与计算通信细粒度重叠，kernel 内用去中心化调度；端到端推理延迟最多降 1.7×，开源 mirage-project/mirage
- **GraCE**（IISc + MSR）：ML 每轮迭代启动数百个短 kernel，CPU 侧启动延迟成瓶颈；GraCE 做三件事——自动代码变换让 ML 应用适配 CUDA Graph、消除图内 kernel 的参数拷贝开销、按成本收益分析选择性启用；25 个 TorchBench/HF/TIMM 负载上相较 PyTorch2 部署 CUDA Graph 的收益翻倍以上，构建在 torch.compile 上、无需改代码
- **VTC**（UIUC + GaTech + Microsoft）：提出 virtual tensor —— 用索引映射而非物理全局内存搬运追踪算子间数据移动，并可无缝与既有计算 kernel 互操作；平均 1.28×（最高 1.93×）加速、推理显存最多省 60%
- **TileLoom**（NUS + ASU + Google + Lumai）：MLIR 端到端框架把 Triton 这类 tile 语言编译到空间数据流加速器，重点不在单 tile 内优化，而在把 tile 实例分布到空间分布式核心上、利用片上网络与分布式内存提升复用；Tenstorrent 两代系统上达到厂商库水平
