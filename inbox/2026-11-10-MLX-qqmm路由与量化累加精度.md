# mlx 11 月首周：Metal qqmm 路由补课（M=1024 达 7–13×）＋ CPU 量化累加精度
- 来源: https://github.com/ml-explore/mlx/pull/4796 ; https://github.com/ml-explore/mlx/pull/4803
- 日期: 2026-11-03 / 2026-11-05
- 标签: #MLX #Metal #量化内核 #qqmm #精度

## 摘要
Metal 上 `qqmm`（两个操作数都量化）过去不看行数一律走 `dispatch_qmv` 向量核，只有 nvfp4 + global scale 在大 M 才进 `qmm`，于是 256/1024 行的形状比 `quantized_matmul` 用的矩阵核慢 6–13×；#4796 把路由对齐到 `quantized_matmul`。同周 #4803 修 CPU affine 量化 matmul 在 bf16/fp16 缓冲里反复舍入的精度丢失（改 fp32 累加 + 每行 float 缓冲）。

## 要点
- 8 个 K×N 形状 geomean（M5 Pro 16 核）：M=1 1.00×（未变），M=16 nvfp4 3.11 / mxfp4 3.91 / mxfp8 3.62×，M=256 6.16 / 9.70 / 10.29×，M=1024 7.48 / 12.24 / 12.77×；M5 Max 低一档（M=16 2.50×）
- 单形状极限：4096×151936（vocab 投影）M=256，M5 Pro nvfp4 108.6 ms → 13.9 ms（7.8×）
- 只影响中等 batch / MoE grouped 量化路径；decode 的 M=1 完全没动
- #4803 触发面：`_qmm_t` 用 `T sum`、`_qmm` 直接写低精度输出缓冲 → 大 K 累积误差；修复附 84 组 dtype/layout/group size/bit 的回归测试
- 版本口径：mlx 最新 tag 仍 v0.32.4（2026-10-14）、mlx-lm v0.32.2（10-16）→ 这批 11 月改动只在 main，未发版
- 口径：数字取自 PR 内自测 benchmark 表，两机型，无第三方复现
