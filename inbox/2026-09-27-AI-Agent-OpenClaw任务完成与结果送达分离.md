# OpenClaw 九月发布：把「任务完成」和「结果送达」拆成两个事实

- 来源: https://docs.openclaw.ai/releases/2026.9.6 （另见 v2026.9.5）
- 日期: 2026-09（v2026.9.5 / v2026.9.6）
- 标签: #AIAgent #Harness #任务状态 #可观测性

## 摘要
OpenClaw 九月的两个 release 集中修「任务状态说谎」问题：任务详情里区分 live 的 Running / Queued / waiting / Finished 与已落盘的历史任务记录，后台静默命令可以被标为 running，延迟到达的活动不再把已完成的工作显示成进行中，并明确 **Finished 只描述执行状态，成功与结果待送达是两件独立的事**，活动不可见本身不等于失败。

## 要点
- 判据原则：执行完成 ≠ 任务成功 ≠ 结果已投递；三者分开表达，避免 UI 用「finished」混淆成功语义（正对 LongLoop 的防虚假完成痛点）
- 任务标识歧义时不猜：含糊的 task id 保持原样处理，宁可不命中也不冒「结果投递到错误任务」的风险；同一物理 store 被多 agent 共享时 title 修复仍有限制
- 取消语义绑定当前控制权与所选执行：缺执行详情的旧 ACP 任务无法经核心任务控制取消，已接受的 stop 可以报告清理仍在进行
- A2A 任务切换模型后，完成结果必须携带 fallback 模型的实际答案，不再只回一句「将使用其他模型」就提前结束
