# FP4 KV cache 的两种叙事：厂商说 <1% 掉点，论文实测掉 8.5 分
- 来源: https://arxiv.org/abs/2611.09825 (代码 https://github.com/OpenBitSys/BitDecoding-FP4)
- 日期: 2026-11 (arXiv 2611.09825)
- 标签: #推理部署 #KVcache #FP4 #NVIDIA #量化

## 摘要
BitDecoding-FP4 把「4-bit KV 为什么掉精度」拆成了三个可分离的误差源，并给出算法+内核的联合设计。它使 NVFP4 KV 在七个 benchmark 上距 BF16 KV 平均 0.5 分以内（MXFP4 1 分以内），而基线 TRT-LLM 原生 NVFP4 在 Qwen3-4B 上掉 8.5 分——说明厂商口径的「<1% 精度损失」依赖的是数据分布和评测集，不是格式本身。

## 要点
- 误差源排序反直觉：query 量化贡献 60% 的 logit 误差，KV 量化反而次要。双残差 query（q = s1·q̂1 + s2·q̂2）把 logit 误差压到 1%，代价是 0.4% 内核开销（第二项塞进第一块 tile 的零填充列，用 stacked MMA 吸收）
- 第二、三个误差：128K 上下文下 E4M3 block scale 会把小概率四舍五入到 0（应下溢感知缩放）；key 的 outlier 需静态平滑 + Hadamard 旋转 + scale search 才能压住
- 系统侧真正见效的改动是转置 softmax：把 S^T 变成 B_k×G 形状，逐线程串行归约换成 warp 级蝶式归约，顺便免费拿到概率量化的 block 最大值——Qwen3-30B-A3B、batch 64、128K 下内核从 3994µs 降到 1040µs（3.8x）
- 端到端：B300 上 Qwen3-4B 3.00x、Qwen3-30B-A3B 2.62x 峰值吞吐（对 BF16 KV），以 vLLM 的 out-of-tree CUSTOM backend 形式落地，不需要改上游
- 对自研栈的含义：FP4 attention 的瓶颈不在 MMA 吞吐而在 softmax 与量化耦合处的串行开销，且 query 侧精度损失占比远高于权重侧的经验值；做 RISC-V 矩阵扩展时若考虑 int4/fp4 attention，转置归约这类数据布局优化比算子本身更值钱
