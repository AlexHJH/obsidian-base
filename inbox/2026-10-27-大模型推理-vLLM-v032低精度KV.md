# vLLM v0.32：低精度 KV cache 全面铺开
- 来源: https://github.com/vllm-project/vllm/releases/tag/v0.32.0
- 日期: 2026-10-18
- 标签: #vLLM #LLM推理 #量化 #KVcache #开源release

## 摘要
v0.32.0 含 814 个 commit、363 位贡献者（121 位新人），主线变化集中在两处：NVFP4/FP8 低精度 KV cache 覆盖到更多架构，以及结构化输出/工具调用解析器改为读 checkpoint 自带模板。节奏上从 v0.30.0（9-22）、v0.31.0（10-05）到 v0.32.0（10-18），约两周一个 release。

## 要点
- NVFP4 KV cache 扩到 SM8x/SM12x，并支持 SM90、SM12x 上的 XQA decode，以及 SM100 上 MiniMax-M3 稀疏注意力；GLM-5.x 默认走 FP8 KV cache
- 新增 `POST /v1/systemone` 端点，对结构化状态回答 choice/noul/score，默认开启，并已适配 Cloudflare/clef-omni、LiquidAI/d1-3B、DiffusionGemma
- 新增 `hf` 工具/推理解析器（`--tool-call-parser hf`、`--reasoning-parser hf`），直接读 checkpoint 的 `response_template`，模型不再需要专属 parser；Python 与 Rust 前端同步
- 承接 v0.30 的 Fast Start（per-GPU 权重缓存守护进程 + `--load-format ipc_cache`，CUDA IPC 映射重启）：冷启动时间正在被当成一等指标
- 对 [[推理引擎格局-vLLM-SGLang]] 的补充：低精度 KV 正从"可选优化"变成默认路径，量化粒度下沉到 KV 层
