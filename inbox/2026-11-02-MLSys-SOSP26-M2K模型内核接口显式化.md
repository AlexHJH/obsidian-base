# M2K：把「模型—内核接口」显式化，符号执行挖出 181 个 CUDA 内存 bug
- 来源: https://arxiv.org/abs/2603.24595
- 日期: 2026-08-29
- 标签: #MLSys #SOSP2026 #CUDA #验证

## 摘要
SOSP'26 论文（arXiv v2，2026-08-29）。前提很硬：LLM 推理系统的模型与 CUDA kernel 独立演进，对 tensor shape 与输入规模的假设经常冲突，产生只在特定 shape 下才触发的内存 bug——能打崩服务、写坏权重、也能被远程利用。M2K 不猜 shape，而是先把"谁决定这个参数"变成静态知识，再做符号执行。

## 要点
- 两段式：**HFProbe** 不依赖 GPU 硬件追踪模型执行，把 kernel 参数分类为 **model-fixed**（架构决定，如 weight 维度）与 **user-variable**（用户输入决定，如 seq_len），输出符号约束；**cuKLEE** 据此做 CUDA 符号执行定位越界
- 扩到数千线程的关键技巧：tensor 建模为**互不相交的内存区**（而非逐字节数组），thread ID 也符号化，避免线程维度的路径爆炸
- 实测：真实 LLM 推理系统中发现 **181 个此前未知 bug**，仅 **9 个误报**；论文口径强调现有 fuzzing 要么不看模型侧调用上下文、要么只测框架不测 kernel
- 方法论可迁移：显式化"隐式接口"是验证的前置条件——不先声明契约，符号执行只能在无约束的输入空间里瞎跑
- 关联 [[NVIDIA-Tensor-Core-TMA与AI指令体系]]（kernel 语义与形状假设）、[[AI编译器2026格局]]（lowering 后 shape 信息丢失是同类根因）
