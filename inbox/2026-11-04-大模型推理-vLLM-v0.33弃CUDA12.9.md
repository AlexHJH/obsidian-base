# vLLM v0.33.0rc3：弃 CUDA 12.9、上 Triton 3.8，投机解码把草稿槽从 token 预算里摘出去
- 来源: https://github.com/vllm-project/vllm/releases/tag/v0.33.0rc3
- 日期: 2026-11-02
- 标签: #LLM推理 #vLLM #投机解码 #CUDA #KVcache

## 摘要
927 commits / 389 贡献者的版本（当前只发到 rc3，正式版未 tag）。两个「不可回退」的工程变化：运行时基线升到 PyTorch 2.14.0 + Triton 3.8.0，同时 CUDA 12.9 的 wheel 与 `-cu129` 镜像全部停发——CUDA 13.0 成为唯一发布形态，CUDA wheel 还改成了对 libtorch ABI 稳定。

## 要点
- 投机解码的实测收益集中在「草稿不占预算」这一处：DFlash/DSpark 不再在 token budget 里预留草稿槽，DeepSeek-V4.1-Flash + DSpark 在 GB300 从 1373 → 3390 output tok/s（PR 自测）
- FLy：可选的有损验证策略，MI355X / B300 上 decode 吞吐 1.04–1.31×；`draft_lm_head_quantization` 在并发 1 时 +18% decode
- 低精度 KV 继续铺开：NVFP4 KV 覆盖 SM8x/SM12x/SM90，GLM-5.x 在 SM100 默认 FP8 KV（KV 内存减半，吞吐 +2.3–5.5%，代价是 TTFT +7–11%）
- ROCm 默认镜像升 ROCm 10.0（7.2 保留为 `-rocm72`），MonoKernel decode 在 MI300X/MI325X 上 2.32× P50 交互性
- 破坏性变更：Medusa 与 MLP speculator 被删、legacy Ray compiled-graph executor 被删；NIXL connector 要求 ≥1.5
- 读法：和 [[推理引擎格局-vLLM-SGLang]] 里「引擎在抢同一批 kernel 级优化」一致——这版的增量几乎全在 attention/MoE 融合与投机解码调度，而不是新特性面
- 口径：数字均为 release notes 内 PR 自测，未独立复现
