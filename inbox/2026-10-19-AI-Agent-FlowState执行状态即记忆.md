# FlowState：把「执行状态」当记忆，替长时程 Agent 省 40% token
- 来源: https://arxiv.org/abs/2609.34565
- 日期: 2026-10-08（v2；v1 2026-09-28）
- 标签: #AI-Agent #长时程 #记忆架构 #上下文工程

## 摘要
Minghao Li 等 8 人提出 FlowState：不再把历史当「可压缩的文本」，而是把执行状态本身做成可跨请求保留、可回访的记忆——语义化类型的状态节点 + 节点间关系 + 指向原始工具观测的引用，把「长期保留」与「按需访问」拆开。同一模型（DeepSeek-V4-Flash）对打全上下文基线：MemoryArena 成功率 +4.55pp、τ³-Bench 通过率 +13.95pp，总 token 消耗反降 43.2% / 40.6%。

## 要点
- 两个机制同处一个执行环：ISU（增量状态更新）按新输入与反馈维护当前状态；PSA（渐进状态访问）在推理中按需逐层展开历史状态与支撑证据
- 关键设计是「引用而非拷贝」：状态节点只存语义与关系，原始工具输出留在外面按引用取——这是 token 降四成、准确率反升的根因
- 动机三条：留全量历史→上下文成本爆；压缩历史→后期要用的细节被压丢；历史相关性本身随任务推进才显现
- 与 [[AI-Agent-2026格局]] 的 harness 主线合流：上下文管理正从「摘要/折叠」走向「显式状态机」，可回退、可审计
- 对 [[LongLoop Console]] 的直接含义：验收契约冻结本质就是「状态节点 + 证据引用」，PSA 式的渐进展开可替代一次性灌全量日志
