# llm-d 上服务 agentic 负载：MTP 把并发前沿右移约 8×
- 来源: https://llm-d.ai/blog/serving-glm-5-2-agentic-workloads-on-llm-d
- 日期: 2026-10（近期）
- 标签: #大模型推理 #agentic #推测解码 #KV卸载

## 摘要
llm-d 用 SemiAnalysis Weka trace 里 219 个生产 Claude Code 会话当负载，在 H200 上以 GLM-5.2-FP8 跑「1P1D / DEP16 / 32 GPU」对比：以「每用户 ≥30 tok/s」为服务底线，多 token 预测（MTP）能撑到并发 128、聚合约 5,647 tok/s，而只靠 CPU 侧 KV 卸载在并发 16 就撞墙（约 561 tok/s）——官方口径 ≥8× 并发、10.1× 聚合输出。

## 要点
- 度量口径是「平均输出速率底线」，不是 TTFT 或尾延迟 SLO → 读这组数字时必须按同一底线比较，不能与 P99 延迟目标混用
- 结论指向 agentic 负载的优化顺序：先用推测/并行解码拉高每用户出词率，再谈靠 CPU 卸载扩并发；单靠卸载只解决容量不解决速率
- 与 [[推理引擎格局-vLLM-SGLang]] 的 KV 分层叙事互补；也与 [[MLX生态2026]] 里「agent 瓶颈是重复处理超长 prompt」的判断同向（缓存复用 + 解码加速两条腿）
- 口径：项目自报、单模型单硬件（H200、32 GPU），未读到指标原始表格
