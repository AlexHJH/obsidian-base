# SGLang 把 KV 池收敛成一套：删掉 ChunkCache，draft KV 融进 target 页框
- 来源: https://github.com/sgl-project/sglang/pulls?q=is%3Apr+is%3Amerged+merged%3A2026-10-09
- 日期: 2026-10-09
- 标签: #大模型推理 #SGLang #KVcache #分页内存 #投机解码

## 摘要
SGLang 的 mem_cache 正在把原先按 attention 形态分裂的多套前缀缓存（RadixCache / SWARadixCache / ChunkCache）收敛成一套 UnifiedRadixCache，并把投机解码的 draft 模型 KV 融进 target 的 page envelope。方向很明确：KV 池当一个内存管理器，而不是每个特性各带一套。

## 要点
- #43199 / #43200 / #43198：disabled full-attention、hybrid-SWA、pure-SWA 三种形态分别由 UnifiedRadixCache 或 PureSWARadixCache 承载；#43201 直接删除 ChunkCache，调度路径里的 `isinstance(tree_cache, ChunkCache)` 一并换掉
- 判据从类型改成能力：调度器改查 supports_swa / supports_mamba / is_tree_cache / is_chunk_cache，缓存类继承关系不再是分支依据
- #37627 / #37628（unified-memory）：draft KV 与 target KV 共用同一 page 池的读写路径，#40491 / #40492 把 EAGLE/EAGLE3、D-FLASH、D-SPARK 接上 → 投机解码不再另占一套显存
- #41593：FCFS 类策略下刷新等待中请求的已缓存前缀 + LRU 驱逐，减少「排队期间前缀被踢掉再重算」
- 口径：依据 GitHub PR 标题与 mem_cache 提交历史（合并日 2026-10-09），未读全量 release notes，也没有公开收益数字
