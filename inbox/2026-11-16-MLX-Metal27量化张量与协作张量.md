# Metal 27：量化权重和 block scale 并进同一个 tensor，协作张量直喂 matmul2d
- 来源: https://developer.apple.com/videos/play/wwdc2026/330 （WWDC26「Optimize custom machine learning operations with Metal tensors」）；https://developer.apple.com/metal/whats-new/
- 日期: 2026-11-16（对照 WWDC26 会话与 Metal What's New 页）
- 标签: #MLX #Metal #TensorOps #量化 #NeuralAccelerator

## 摘要
WWDC26 这场课把 Metal Tensor API 的量化路径讲全了：MTLTensor 现在能带一个 scale plane（FP8 E8M0、按 block 缩放，示例 32×1），量化数据与 scale 打包在同一个 tensor 对象里，`matmul2d` 直接吃量化 tensor 并自动走硬件加速。同一版里协作张量（cooperative tensor）不再需要先落 threadgroup memory 就能作为 matmul 输入。

## 要点
- 硬件前提写得很直白：Neural Accelerator 是 M5 里长在每个 shader core 内部的新单元，定位是 dense compute-bound 工作负载（点名 LLM 的 prefill）；M5 Pro / M5 Max 均具备
- dtype 时间表：4/8-bit 整数在 macOS/iOS 26 的一次更新里加入；macOS/iOS 27 再加 4/8-bit 浮点与 2-bit 整数，新类型对齐要求更严，文档要求单独核
- scale plane 用法：建描述符 → 填 dataType + blockFactors → 附成 auxiliary plane → 挂回主 descriptor；切片时 data 与 scales 按 block size 同步切
- FlashAttention 这个例子最能说明取舍：每个 simdgroup 独占完整行（`execution_simdgroup` scope），中间矩阵放协作张量、用 `reduce_rows` + `map_iterator` 在原地算 SoftMax，然后**直接**当 matmul 的输入——macOS 26 时代这一步必须先写回 threadgroup memory
- 对 MLX 的意义：MLX 在 M5 上正是靠 TensorOps/MPP 打到 Neural Accelerator，底层把「量化 + 缩放」收成一个 tensor 后，融合 kernel 少一次往返；但 MLX 当前版本是否已用上 27 的新 dtype 与协作张量直连，笔记里未核实
- 口径：以上均为 Apple 官方会话/文档陈述，未做本机实测；性能数字（4× TTFT 等）是 Apple 对 M5 vs M4 的宣传口径
