# 光路 KV cache 网络：把 OCS 重配置延迟藏进 prefill
- 来源: https://arxiv.org/abs/2610.18444
- 日期: 2026-10-18
- 标签: #LLM推理 #KVcache #PD分离 #光交换 #网络

## 摘要
PD 分离下每个请求的 KV cache 都要从 prefill GPU 搬到 decode GPU，coding agent 一轮甚至要搬整个长上下文的 KV；在超售的 packet fabric 上这部分直接计入 TTFT。作者用光电路交换（OCS）给每次传输一条全速独占电路，并把机械 OCS 几十毫秒的切换时间**藏在 prefill 计算过程中**：预留调度器在 prefill 还没算完时就锁定电路，KV 就绪时电路已就绪。

## 要点
- 每张 GPU 通过自己的 WDM 光模块接入，**一对光纤**承载全部波长 → 布线复杂度与端口数解耦
- 评估用真实 serving trace，prefill 时间在 H100 上实测，再模拟 GPU 集群
- 结果：达到带自适应路由的 400G packet fabric 同等性能，成本只要 2:1 超售 fabric 的 **0.55–0.78 倍**，且能容忍 384 端口机械 OCS 的 **50ms** 重配置延迟
- 视角：KV 搬运的瓶颈从"带宽够不够"转为"电路能否提前预约"——调度器要与 prefill 的时长预测耦合
- 与 [[HBF-NAND-AI推理内存2026]] 呼应：一端是内存层级扩容，一端是搬运介质换光，都是围着 KV 的体积与流动做文章
