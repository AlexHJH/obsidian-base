# SGLang v0.5.23：把整步 decode 压成一个持久 kernel，单用户解码 +44%(GB300)/+75%(MI350X)
- 来源: https://github.com/sgl-project/sglang/releases/tag/v0.5.23
- 日期: 2026-11-02
- 标签: #LLM推理 #SGLang #MegaKernel #MoE #TPU

## 摘要
1007 PR / 257 贡献者。最值得记的是「low-latency mode」：可选插件 sgl-nvidia-mega / sgl-amd-mono 把 DeepSeek-V4.1-Flash 的 decode 做成融合的 persistent kernel，单用户解码在 GB300 快 44%、MI350X 快 75%——这是把整层循环的 launch 开销当成一等问题的做法。

## 要点
- Paged Experts（可选）：让超出显存的 MoE 模型跑在单张消费级卡上，比 CPU offload 快最多 30×——把「专家分页」从研究原型推到可用开关
- MoE 首 token：DeepSeek-V4.1-Flash、GLM-5.3-Flash、gpt-oss 在 H200 上 8K prompt 的 TTFT 提前 30–58%
- 硬件面第一次上岸 Google TPU7x（SGLang-TorchTPU，PyTorch 原生插件），镜像 `v0.1.0-tpu`
- MLA + decode context parallelism 的 prefix cache 可落到 HiCache 文件式 L3；量化 MoE（FP8/NVFP4）可挂 LoRA
- 与 vLLM 同一周的对照：vLLM 走「更多 kernel 特化 + 低精度 KV」，SGLang 走「整步融合成单 kernel + 专家分页」，两边都在把 GPU 当「launch 昂贵的加速器」而非通用并行机
