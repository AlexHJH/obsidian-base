# GSan 给 async proxy 单开一个时钟：TMA 写完不等于对方看得见
- 来源: https://github.com/triton-lang/triton/pull/12754、/pull/12787
- 日期: 2026-11-16
- 标签: #Triton #正确性验证 #Sanitizer #TMA #内存模型

## 摘要
GSan 原来把「generic store 之后跟一次 TMA 访问」当成已排序，于是漏报「缺 proxy fence」这一整类错：泛用 store 与 async proxy 是两条可见性路径，acquire 拿到对方的 generic 写，并不会让它对本地 async proxy 可见。修法是给 async proxy 记独立向量时钟。

## 要点
- 三条传播规则：全局 async proxy fence 把 generic 时钟发布到 async 时钟；release/acquire 只搬 generic 时钟；已完成的 launch dependency 同时初始化两个时钟
- 影子单元不增大：靠 per-access proxy tag 在同一格子里区分 generic 与 async 的读者历史；Gluon 侧新增 `fence_async_global()` 及配套 IR/运行时插桩
- 边界划得很清楚：仍是「同步语义下的异步 op」建模，检测「缺 async wait」明确列为后续工作——即本文只解决 fence 漏检，不解决 wait 漏检
- 容量账：#12787 把分布式 GSan 从 12-bit clock ID 扩到 16,384 个、支持 64 逻辑设备、每 rank 状态步长 1→4 GiB；10 个池共用 97 TiB VA 预留（29 TiB 数据 + 68 TiB 影子），物理内存按实际分配
- 池大小公式 `data + (data/granularity) × cell`，普通格 24 B、write-once 格 4 B；release flag 塞进普通格 metadata word 才保住了 16-bit epoch
- 判读：这条把「PTX 里 async proxy 是独立一致性域」这个硬件事实变成了编译器的显式模型——与 [[NVIDIA-Tensor-Core-TMA与AI指令体系]] 里 mbarrier/proxy fence 的手工编排是同一个约束，只是换到验证器里表达
- 口径：两个 PR 均 open；本地跑通 113 个分配器测试 + 54 个 GPU sanitizer 测试，作者明说 64 卡全量未验证
