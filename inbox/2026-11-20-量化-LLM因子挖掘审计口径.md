# 审计一篇 LLM 因子挖掘项目：Sharpe 2.23 vs 2.43 只是两种口径，不是架构优劣
- 来源: https://arxiv.org/abs/2610.29500
- 日期: 2026-10-21
- 标签: #量化 #因子挖掘 #LLM #评测方法 #可复现性

## 摘要
港大 Yufeng He 对一个留存下来的 LLM 因子挖掘项目做了三层审计：历史 run 计数、结果保留方式、以及独立界定范围的全 cohort 复算。结论是该项目的「pipeline 2.23 vs swarm 2.43」均值 Sharpe 比较不成立——前者平均的是 kept 候选，后者平均的是每轮最大正值，且分母不同源。发布版 1,837 条 OOS 目录 0 条负 Sharpe，是因为写盘前把 OOS≤0 直接丢掉了。

## 要点
- 口径错配可复原：pipeline 收集 67 条 kept 候选 Sharpe（均值 2.227），swarm 收集 20 条「每轮正最大值」（2.433）；最大值也不同源——pipeline 的 evaluated round 摘要能到 3.171，swarm 的 4.206 是 round max 而非 kept
- 分母不可比：67/234 的成功口径 vs 20/816 的返回口径（含失败与符号翻转评估），报告未留 success-only 分母 → 接受率差异未获证实
- 保留偏差是硬的：checkpoint 有 2,016 条表达式含 368 条 OOS 负；仅在 checkpoint 出现的 368 条全负、仅在目录出现的 189 条全正、1,648 条共有零符号分歧；且目录只有 1,037 条满足论文自称的 IS 规则（Sharpe≥2、Fitness≥0、Turnover≤500）
- 全 cohort 复算（1,047 条冻结清单，40 只 A 股、2023–2025 共 727 个交易日、标签为 5 日调整收盘涨幅）：923 条可评分、99 条有效日期不足、25 条算子不支持；可评分的 671 条正、252 条负 signed mean rank-IC，中位 0.0148
- 修一个真 bug：公开实现的 conditional 算子在 scalar 分支上把 panel 当单个布尔，57 条数值报错；用带版本号的标量广播修正后全量重跑（不只重跑「有希望的失败」），另 990 条诊断不变
- 对照杀伤力最大：未训练参考信号同样正 IC（换手量 0.0234、20 日名义涨幅 0.0229）→ 正 IC 本身不构成 agent 增量技能，更不是盈利证据；作者拒绝给架构排名
- 判读：这是「防虚假完成」在量化侧的教科书案例——同一份产物能支撑审计，却支撑不了性能排名；要救的是 metric grain、不可变 cohort 记账、provenance，而不是再加种子或显著性检验
- 口径：作者自陈单一市场 + 便利股票池，公开算子语义替代原生评估器，5 日标签重叠故未做因子独立性显著检验，参考信号是 coh分析之后补设的
