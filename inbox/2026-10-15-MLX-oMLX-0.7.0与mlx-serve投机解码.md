# oMLX 0.7.0 持久化 ANE 编译缓存 + mlx-serve 四种投机解码
- 来源: https://github.com/jundot/omlx/releases ; https://github.com/ddalcu/mlx-serve ; https://mlxserve.com
- 日期: 2026-09-30（oMLX 0.7.0）
- 标签: #MLX #AppleSilicon #端侧推理 #ANE #投机解码

## 摘要
oMLX 0.7.0 新增可选的持久化 ANE 编译缓存：把已编译的 Qwen ANE 程序经 Apple AOT cache 跨进程复用，新进程模型加载时间降 53%–66%（M1 Ultra / M1 Max / M2 Max），输出逐字节一致。同期 mlx-serve 把投机解码做成四种可切换路径，Mac 侧竞争重心进一步移向服务层。

## 要点
- 开启方式：Advanced Cache 设置或 `OMLX_QWEN35_ANE_COMPILE_CACHE=1`，下次重启生效；0.7.0 同时加快「其他请求生成时」的新请求准入
- 社区即时反馈：M3 Ultra 上 qwen3.8-flash-next 从 7 月约 20–25 tps 提到约 75 tps（单机自测）；oMLX 官方口径 8 并发生成加速约 4.14×
- mlx-serve（ddalcu）：原生 Zig 服务 + Swift macOS app、无 Python；OpenAI + Anthropic 双协议，并原生说 Ollama API（/api/chat 等），带 Prometheus 兼容指标
- 四种投机解码：PLD（n-gram，全架构可用）、模型自带 draft companion、Gemma 4 专用 drafter、Qwen 原生 MTP；自报同权重比 LM Studio 几何平均 +26%
- 判据不变：Mac 的差异化正在「缓存复用 + 投机解码」的服务层，而非裸 decode 吞吐；两家数字均为单机自测
