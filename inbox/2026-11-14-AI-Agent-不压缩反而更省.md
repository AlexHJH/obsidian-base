# 别默认压缩：生产环境实测"全量保留"更省更准

- 来源: https://www.louisbouchard.ai/context-engineering-2026
- 日期: 2026-08-18
- 标签: #AI-Agent #context-engineering #prompt-caching #评测方法

## 摘要
一篇带完整评测的方法论复盘：在生产 AI 家教 agent 上跑 11 种上下文策略、660 轮，结论是 prompt caching 时代"什么都不做"（保留全量历史）在成本、首 token 延迟、记忆召回三项同时最优。真正付钱的是不需要模型调用的那一档——给工具输出设固定上限。

## 要点
- 全量历史 vs 生产压缩预设：$0.11 vs $0.24 每轮，TTFT 17s vs 21s，记忆探针 92% vs 38%；盲评打分仍说"答案不错"——这正是不能靠眼看的原因。
- 损伤跟"有损重写次数"成正比，不跟上下文大小成正比：无压缩事件全对，2-3 次仍能答，5-6 次只对 1/3；每次把 ~150k token 压到 ~1.7k，约 90:1。
- 失败时压缩组的活上下文是 95k-195k token，全量组 363k-879k 却全对——"窗口不够"不是真因，重写才是。
- 廉价的赢法：把每个工具输出截到固定长度，每轮成本降 38%（$0.189→$0.117），15 条配对轨迹赢 14 条，缓存命中率 96.0%→95.9%，召回不变。
- 决策阈值：缓存输入价格低于约 $0.55/M token 时全量保留更便宜；DeepSeek 价位下赢 13%，前沿价位持平。压缩只应对"窗口装不下/质量真衰减"。
- 方法可复用：turn 0 埋一个事实，撑过压缩触发点后在 turn 11 探针，只给"问题+答案+判分标准"给盲评。与 [[MLSys2026论文精选]] 里 KV 复用的动机互为镜像。
