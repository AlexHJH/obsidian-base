# MLX 0.32.x 版本漂移坑：多模态图像输入回归 + fork 静默降级

- 来源: https://mlx-optiq.com/changelog , https://www.university-365.com/post/mlx-apple-open-source-array-framework-for-machine-learning-on-apple-silicon , https://ml-explore.github.io/mlx
- 日期: 2026-09-30（mlx-optiq changelog 滚动更新；university-365 复测版本 mlx 0.32.1，2026-09-11）
- 标签: #MLX #版本管理 #量化 #多模态

## 摘要
第三方量化工具 mlx-optiq 的 changelog 记了两类典型事故：MLX 核心改掉 `mx.repeat` 签名（现在要求 int）后，mlx 0.32.2 上所有 Qwen3.5/3.6 视觉模型的图像输入直接坏掉（vendored tower 传的是数组）；同时安装第三方 fork 会静默降级 mlx-lm 并移除部分模型族。

## 要点
- 核心版本会悄悄打破 vendored 组件的隐式契约（这里是量化/包装后的 vision tower）——升级 MLX 必须对拍多模态输入，纯文本 smoke test 抓不到
- 生态版本现状（2026-09 复测口径）：mlx 0.32.1、GitHub 28.4k stars / 2.2k forks / 262 contributors；官方文档已到 0.32.3——判版本要同时看 wheel、docs 与 metallib 三者（自建 metallib 曾在 M5 NAX 路径出乱码，见 [[MLX生态2026]]）
- fork 陷阱：第三方工具可能连 mlx-lm 一起降级、模型族静默消失 → 安装后核 pip 解析结果，别只信 README 的兼容声明
- 落地建议：锁 `mlx` + `mlx-lm` 版本、独立 venv（本机语音服务即此模式）；升级流程固定为文本对拍 → 多模态对拍 → 量化输出对拍
