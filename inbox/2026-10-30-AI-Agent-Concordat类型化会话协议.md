# Concordat：把 agent 的接口写成有限状态协议，在运行时强制执行
- 来源: https://arxiv.org/abs/2610.37461
- 日期: 2026-10-29
- 标签: #AIAgent #安全 #类型系统 #协议 #Guardrail

## 摘要
"改账号前必须拿到用户明确确认"这类规则现在只写在 prompt 里，可靠性等于模型自觉程度。Concordat（Python 库）把 agent 当作接口是**有限状态协议**的对象（typestate / session types 思路），运行时施加约束：每一轮只提供当前状态合法的工具，越界的调用在有副作用之前就被拒绝。

## 要点
- 人的决策只能"请求"不能"执行"；token 与工具调用预算按 handoff 线性切分并计费
- 协议在定义时静态检查；子类若可能绕过父类协议则**定义即被拒**——行为层面的 Liskov 替换原则
- τ-bench 50 个航空任务 + 加压客户（诱导跳过确认）：标准 agent 在 gpt-4.1 上 50 个任务里 13 个未拿 "yes" 就改单，Claude Haiku 5.5 上 128 次里 29 次；Concordat agent 为 0，任务成功率无显著差异
- 关键发现：**τ-bench 自己的 reward 基本检测不到这些违规**——基准通过率掩盖了不规范操作
- 对 [[AI-Agent-2026格局]] 的补充：约束从 prompt 搬到语言/状态机层，才谈得上可验证；开源实现
