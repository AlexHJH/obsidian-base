# 「谁在调度记忆？」MemSidecar 把记忆调度从主 agent 循环里摘出去
- 来源: https://arxiv.org/abs/2611.00779
- 日期: 2026-10-31（南京大学 / Northeastern，12 页 4 图）
- 标签: #AIAgent #Memory #LongHorizon #调度

## 摘要
现有记忆工作只研究怎么存、怎么更新、怎么检索，却默认「取记忆」这个动作由主 agent 自己发起——它得先意识到需要记忆、发起查询、再等结果返回，调度负担和等待时间全压在任务执行的关键路径上。MemSidecar 把记忆调度拆成独立的外挂 sidecar，给出两种可各自选用的模式：**Hooks** 在执行事件命中预置条件时直接把绑定的记忆条目投喂给主 agent；**Foresight** 用一个独立 agent 预测接下来可能的问题、并行检索并放进缓存，等真实请求到达时只投递命中且仍有效的结果。

## 要点
- 数字：MCP-Persona 上 Hooks 得 41.23%、Foresight 得 44.34%，同时降低执行成本与延迟
- 机制上等价于把 CPU 的「预取 + 条件触发」搬到记忆层：检索从同步调用变成异步预热/事件驱动，主 agent 不再为「想起来去查」付延迟
- 与两天前那篇 VeriHarness 同构：一个决定「验证何时介入」，一个决定「记忆何时介入」，共同点是把控制权从主循环里切出去
- 对 [[LongLoop Console]] 的映射：验收契约、上下文注入同样可以做成 sidecar——按事件（改了哪个文件、跑到哪一步）绑定条目，而不是靠主 agent 自觉
- 口径：摘要只报了 MCP-Persona 单一 benchmark 的两个分数，缺 baseline 与消融，收益幅度待读正文确认
