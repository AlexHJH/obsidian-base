# vLLM 0.34：KV cache 不再「按公式估」，改为启动后按剩余显存实测
- 来源: https://github.com/vllm-project/vllm/releases （v0.34.0，2026-11-16）
- 日期: 2026-11-16
- 标签: #推理部署 #vLLM #KVcache #显存管理

## 摘要
v0.34.0 一次改了三个深层默认值：extensible KV cache 默认开启（预热后按实际空闲显存定容，不再用 `gpu_memory_utilization` 的固定比例推算）、该参数默认 0.9 → 1.0、block size 16 → 64。合计 1,061 commits / 412 contributors，Model Runner V1 被彻底删除，MRV2 成为唯一 GPU 路径。

## 要点
- 升级动作是删配置而不是加配置：多数场景应直接移除 `gpu_memory_utilization`；`VLLM_USE_V2_MODEL_RUNNER=0` 现在启动即失败，V1 logits processor 需迁到 `vllm.v1.worker.gpu.sample.logits_processor`
- 收益与代价写在同一行：GLM-5.3 系构建长 prompt TTFT 1.24~1.40×，但 release note 自己警告「per-token decode latency 可能上升」——容量变大后并发放开，延迟会在某个并发点突然跳变，那个 cliff 得自己测
- 投机解码侧改动更实用：suffix decoding 走 MRV2 + GPU speculator（不再需要 Arctic Inference）、`register_speculative_method` 插件 API、MRV2 draft speculator 支持 CUDA graph、draft KV cache 跟随目标模型 dtype（FP8 目标即 FP8 draft）
- 破坏性变更：ROCm 7.2 镜像下线、要求 huggingface_hub ≥ 2.0.0；ROCm 的 paged attention 仍用 block size 16
