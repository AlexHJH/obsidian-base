## Ollama 0.19 全面拥抱 MLX
Apple Silicon 推理后端从 llama.cpp 切换至 MLX，MoE 模型 decode 从 3.19 → 23.39 tok/s（~7x）。自动路由 GGUF→llama.cpp、safetensors→MLX。Rapid-MLX 作为替代品在 M3 Ultra 上再快 2-4.2x。
- int4 量化基准：prefill 1851 tok/s / decode 134 tok/s，相比 llama.cpp 后端约 2x 提速（整理自 [[inbox/2026-06-19-Ollama切换MLX后端]]）

## M5 神经加速器接入 MLX
整理自 [[inbox/2026-06-19-MLX接入M5神经加速器]], [[inbox/2026-06-24-MLX-M5-NeuralAccelerators加速本地推理]]
- Apple ML 团队在最新 macOS beta 启用 MLX 对 M5「神经加速器」的支持
- 神经加速器位于 M5 GPU 内，专职 GEMM 矩阵乘法（LLM 推理核心算子）；M5 Max 40 核 = 40 个加速器
- 官方在 24GB M5 MacBook Pro 对不同规模/架构 LLM 基准，与同配 M4 对比
- 基准结果：LLM 推理提速 19–27%，首 Token 延迟（TTFT）最高提升约 4x；M5 Max 内存带宽 614GB/s（decode 受带宽、prefill 受算力制约）
- 软硬协同推进端侧推理性能，关联 [[AI芯片推理硬件2026全景]]
- 生态扩张：Ollama 0.19（2026-03）切 MLX backend；mlxcel v0.1.0（2026-05-28）Rust 原生引擎；WWDC 2026 推 Core AI（Core ML 继任者），与 MLX 在端侧推理形成竞合
- 整理自 [[inbox/2026-06-27-MLX-M5神经加速器支持]]

## Ollama 0.19 MLX 后端详细基准（2026-07 归档）
整理自 [[inbox/2026-07-09-MLX-Ollama切换MLX引擎]]
- M5 Max + NVFP4 量化实测：prefill 1154→1810 tok/s，decode 58→112 tok/s (Qwen3.5-35B-A3B)
- M5 Neural Accelerators 首 token 延迟领先 llama.cpp Metal 后端 4.06×
- 小模型优势明显（14B 以下 MLX 领先 20-87%），27B 以上因内存带宽瓶颈趋同
- 生态局限：模型覆盖不如 llama.cpp，社区工具链仍在追赶

## BaseRT：纯 C++ Metal 原生推理运行时（2026-07-16 归档）
整理自 [[inbox/2026-07-13-MLX-BaseRT最快推理运行时]]
- 零依赖 MLX/PyTorch/CoreML，直接基于 Metal API 的 LLM 推理引擎
- M4 Pro 上 decode 比 llama.cpp 快 1.56×、比 MLX 快 1.35×；MoE prefill 快 1.81×
- 针对统一内存拓扑做 chip-specific kernel fusion 和零分配 decode loop
- 支持 Qwen3/Llama 3.2/Gemma 4，覆盖 Q2-FP16 八种量化格式

## Apple Core AI 三梯队确立（2026-07 归档）
整理自 [[inbox/2026-07-05-MLX-Apple-CoreAI端侧推理三梯队]]
- WWDC 2026 发布 Core AI 框架，Core ML 的 Transformer 继任者，支持 3B–70B 参数模型全平台端侧运行
- Apple 端侧推理三梯队成型：Core ML（经典 ML）→ Core AI（Transformer）→ MLX（研究/自定义权重）
- Core AI 提供 Swift 统一 API，覆盖 CPU/GPU/Neural Engine；内置 AOT 编译 + Xcode 性能分析，首发加载延迟大幅降低
- MLX 获 WWDC 三场专场（分布式推理/本地 Agent/Swift 数值计算），生态地位进一步升级
