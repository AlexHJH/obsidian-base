## Ollama 0.19 全面拥抱 MLX
Apple Silicon 推理后端从 llama.cpp 切换至 MLX，MoE 模型 decode 从 3.19 → 23.39 tok/s（~7x）。自动路由 GGUF→llama.cpp、safetensors→MLX。Rapid-MLX 作为替代品在 M3 Ultra 上再快 2-4.2x。
- int4 量化基准：prefill 1851 tok/s / decode 134 tok/s，相比 llama.cpp 后端约 2x 提速（整理自 [[inbox/2026-06-19-Ollama切换MLX后端]]）

## M5 神经加速器接入 MLX
整理自 [[inbox/2026-06-19-MLX接入M5神经加速器]], [[inbox/2026-06-24-MLX-M5-NeuralAccelerators加速本地推理]]
- Apple ML 团队在最新 macOS beta 启用 MLX 对 M5「神经加速器」的支持
- 神经加速器位于 M5 GPU 内，专职 GEMM 矩阵乘法（LLM 推理核心算子）；M5 Max 40 核 = 40 个加速器
- 官方在 24GB M5 MacBook Pro 对不同规模/架构 LLM 基准，与同配 M4 对比
- 基准结果：LLM 推理提速 19–27%，首 Token 延迟（TTFT）最高提升约 4x；M5 Max 内存带宽 614GB/s（decode 受带宽、prefill 受算力制约）
- 软硬协同推进端侧推理性能，关联 [[AI芯片推理硬件2026全景]]
- 生态扩张：Ollama 0.19（2026-03）切 MLX backend；mlxcel v0.1.0（2026-05-28）Rust 原生引擎；WWDC 2026 推 Core AI（Core ML 继任者），与 MLX 在端侧推理形成竞合
- 整理自 [[inbox/2026-06-27-MLX-M5神经加速器支持]]

## BaseRT：纯 C++ Metal 原生推理运行时（2026-07-16 归档）
整理自 [[inbox/2026-07-13-MLX-BaseRT最快推理运行时]]

## 投机解码实测：M5 Max 70B 4bit 45→102 tok/s（2026-09-18 归档）
整理自 [[inbox/2026-09-18-MLX-投机解码M5实测与调参]]

## M5 张量核 BaseRT 与 Thunderbolt 5 RDMA 集群（2026-09-23 归档）
整理自 [[inbox/2026-09-20-MLX-BaseRT-M5张量核Metal4内核]]、[[inbox/2026-09-20-MLX-Thunderbolt-RDMA分布式推理与JACCL]]
- BaseRT（arXiv 2607.19438，2026-07-21）：M5 每个 GPU 核心都内置 Neural Accelerator（经 Metal 4 tensor API 暴露的片上矩阵单元），作者用无框架的原生 Metal 运行时 + 手写 Metal 4 张量核内核（dense/MoE GEMM、flash-attention prefill）把计算密集路径路由上去，访存受限的 decode 留给原有内核
- 实测（Apple M5 Pro，15 组配置，Qwen3 / Qwen3.5-3.6 / Llama 3.2 / Gemma 4，<1B–35B）：prefill 最高为 llama.cpp 的 6.4×、MLX 的 3.9×；decode 最高 1.75× / 1.33×，MoE 收益最大（以矩阵乘法为主，正落在张量核射程内）

- 分布式三件套（WWDC26 Session 233 产品化）：物理互连 Thunderbolt 5（延迟敏感选 mesh、带宽敏感选 ring）→ 传输协议 RDMA over Thunderbolt（macOS 26.2+，需手动启用并重启）→ 通信后端 JACCL 集合通信库；`mlx.launch --auto-setup` 自动 SSH 探测各机、关闭 Thunderbolt Bridge、逐链路配 RDMA 并生成 hostfile
- 官方实测四节点分布式推理最高约 3 倍加速，可跑单机装不下的万亿参数级模型（DeepSeek 1.6T 权重需 800GB+）；对 agent 的另一价值是把 prefill 并行化，直接加速 agentic loop 里的工具结果处理
