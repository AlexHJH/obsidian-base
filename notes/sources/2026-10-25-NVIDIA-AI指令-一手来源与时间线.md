[官方 Toolkit Archive](https://developer.nvidia.com/cuda-toolkit-archive/)将 CUDA 13.4.2 标为 2026 年 9 月，早于研究截止日；这与网页的访问/抓取日期不同。归档页面中的 PTX 标题明确为 9.4。选择固定 13.4.2 旨在保证可复核，不声称它是截止日最新补丁。

应分别记录 Toolkit 版本、PTX ISA 版本、目标 SM、编译器/库版本和硬件型号。规范新增可编程接口并不证明对应产品已可购买，也不能证明旧 GPU 支持该接口。滚动 `latest`、CCCL `unstable` 文档作为导航；版本或发布日期结论优先使用归档和 release 记录。

前半段使用版本而非编造精确日期；历史架构说明是理解当前数据流的背景，不充作 2026 年的新事件。

## Tensor Core / TMEM 来源组

1. [PTX 8.7 tcgen05 章节](https://docs.nvidia.com/cuda/archive/12.8.0/parallel-thread-execution/index.html#tensorcore-5th-generation-family-instructions)：核验 TMEM、参与范围、kind/shape、dense/sparse 和 target。
2. [PTX 9.4 当前基线](https://docs.nvidia.com/cuda/archive/13.4.2/parallel-thread-execution/index.html)：核验 UE5M3、ti16、collector/decompress、spcompress、exclusive 与新 multicast 等版本变化。必须逐指令读 target notes，不能整章统一加到 SM100。
3. [Blackwell compatibility guide，CUDA12.8](https://docs.nvidia.com/cuda/archive/12.8.0/blackwell-compatibility-guide/index.html)：区分普通 PTX 可移植性与架构专属目标。
4. [CuTe MMA atom](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/cute/0t_mma_atom.html)：Operation、Traits、thread/value layout 与 tile 组合；访问快照。
5. [warp MMA 教程](https://docs.nvidia.com/cutlass/latest/media/docs/pythonDSL/guides/mma/wmma_programming.html)、[WGMMA 教程](https://docs.nvidia.com/cutlass/latest/media/docs/pythonDSL/guides/mma/wgmma_programming.html)、[tcgen05 教程](https://docs.nvidia.com/cutlass/latest/media/docs/pythonDSL/guides/mma/tcgen05_programming.html)：按架构阅读对应编程模型；不能据滚动教程断言所有旧版本 API 一致。
6. [Blackwell SM100 GEMM 功能](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/blackwell_functionality.html)：低精度和 block-scale 的教学入口；峰值倍率是文档规格，不是本次 benchmark。

优先检查：warp/warpgroup 集体参与、单 issuer 与操作范围的区别、register/SMEM/TMEM 操作数位置、scale/metadata 独立依赖、MMA 与 TMEM ld/st 的完成区别。

## TMA / im2col / 同步来源组

1. [PTX8.4 tensor im2col](https://docs.nvidia.com/cuda/archive/12.4.0/parallel-thread-execution/index.html#tensor-im2col-mode)：普通 im2col 的 tensorCoords、offset、bounding box、pixels-per-column。主笔记两组 NHWC 算例是基于这些语义的原创手算，不是从文档复制的实验结果。
2. [PTX8.7 cp.async.bulk.tensor](https://docs.nvidia.com/cuda/archive/12.8.0/parallel-thread-execution/index.html#data-movement-and-conversion-instructions-cp-async-bulk-tensor)：普通模式与 .w/.w::128 的参数和目标区别。
3. [CUDA13.4.2 Driver API Tensor Map](https://docs.nvidia.com/cuda/archive/13.4.2/cuda-driver-api/group__CUDA__TENSOR__MEMORY.html)：opaque descriptor、编码入口、参数约束；以 API 中的精确对齐/范围限制为准。
4. [CUDA13.1 修改 tensor map 的协议](https://docs.nvidia.com/cuda/archive/13.1.0/cuda-programming-guide/04-special-topics/async-copies.html#usage-of-a-modified-tensor-map)：descriptor 更新的 tensormap proxy 发布/获取，不与数据的 async-proxy fence 混用。
5. [CUDA async copies](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/async-copies.html)、[async barriers](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/async-barriers.html)：高层 API 教学。当前语义同时应与固定 PTX9.4 对照，不用滚动页证明首次发布年月。
6. [CuTe TMA tensors](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/cute/0z_tma_tensors.html)、[CUTLASS pipeline](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/pipeline.html)：坐标 layout、full/empty stage 与 producer/consumer 协作。
7. [CCCL barrier](https://nvidia.github.io/cccl/unstable/libcudacxx/extended_api/synchronization_primitives/barrier.html)、[tcgen05.commit](https://nvidia.github.io/cccl/unstable/libcudacxx/ptx/instructions/tcgen05_commit.html)：API 导航，unstable 状态要保留；指令合法性以固定 PTX 为准。

关键审查点：arrival 与 bytes 是两笔账；store 的 wait.read 仅保证源读取；wgmma.fence 不负责普通 shared 写到 async proxy 的全部可见性；tcgen05.commit 使用 arrive::one，不是 TMA 的 complete_tx::bytes。PTX9.4 的可选 descriptor-read bulkgroup 追踪不能取代 TMA load 数据完成的 mbarrier。

## 本次未完成的实验与不能推出的结论

- 没有 GPU 实测；没有确认任何用户设备、驱动或本地环境。
- 没有跑 im2col GPU oracle；手算只校核采样坐标和逻辑输出尺寸。
- `.w` halo 的精确 shared footprint、transaction bytes 与具体 swizzle 组合留给目标平台验证，不用普通 im2col 公式直接替代。
- 没有验证每一条新 qualifier 的所有 target；因此新特性只作版本化索引，不承诺 SM100/SM120/SM107 系列互通。
- 没有将纸面 Tensor Core 峰值、TMA 存在或编译器 wrapper 存在解释为模型端到端加速。
- 没有复制论文/PDF 全文，也没有纳入私人账号、设备或上传文件内容。

后续增加证据时应记录原始链接、版本/commit、发生日期、核验日期、证据层和未验证项；更新规范理解时保留旧快照，说明究竟改变了指令、target、布局、同步还是性能条件。
