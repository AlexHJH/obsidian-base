## MLIR Auto-Tuning（EuroLLVM 2026, MLIR Workshop）
Intel 在第7届 MLIR Workshop 展示面向 Battlemage GPU 的端到端 auto-tuning：
- Linalg → LLVM IR 的 auto-tuning 框架，用 tuneable "knob" ops 编码优化空间自动搜索最优 tiling
- 无需用户手动指定 tiling，上游 MLIR 即可达 SOTA 框架的 kernel 性能
- ASTER：基于 MLIR 的汇编工具链；Roofline 开源 mlir-track-src 追踪 pass pipeline 中的操作变换
- 关联 [[inbox/2026-06-19-Triton跨厂商基准与形式化验证]]（编译器验证方向）
- **编译优化自动化新进展（2026-07 归档）**：多阶段序列 RL 将 MLIR pass 编排建模为 MDP，自动搜索最优 pass 序列（已对接 IREE）；Lighthouse 框架提供端到端 MLIR 编译器测试基础设施。整理自 [[inbox/2026-07-05-编译器-MLIR优化自动化EuroLLVM2026]]

## TileLang：Tile 级 Kernel DSL（ICLR 2026）
整理自 [[inbox/2026-06-26-编译器-TileLang-tile级kernel-DSL]]、[[inbox/2026-07-27-AI编译器-TileLang崛起]]
- 北大/帝国理工/TileAI/微软研究院：tile 级 kernel 编程 DSL，Pythonic 语法，编译栈基于 TVM
- 核心创新：调度空间（线程绑定/布局/tensorize/流水线）与数据流解耦——开发者只写数据流，编译器自动搜索最优调度
- H100 比 Triton 平均 3.02×（最高 10.58×），AMD GPU 平均 2.65×
- FTG（融合 tile 级数据流图）驱动「tile 推荐」（硬件感知默认）+「tile 推断」（约束传播自动补全）
- 已验证 Hopper(Auto TMA/WGMMA)/A100/V100/RTX 4090/AMD MI250/MI300X
- v0.1.11（2026-06）已支持 CuTeDSL backend，可编译到 NVIDIA CUTLASS
- 集成 Z3 定理证明器，SMT 符号推理进行自动正确性验证
- 7 月 HyperAI 沙龙 TVM/Triton/TileLang 首次同台竞技，三足格局初现
- 与 Triton 互补：Triton 提供细粒度控制，TileLang 补足显式低层原语（显存放置/数据搬运/并行调度）

## TVM vs XLA vs Triton 三路线对比（Modular 系列）
整理自 [[inbox/2026-06-15-AI编译器TVM-XLA-Triton格局]]
- **XLA**：Google 主导，与 JAX/TF 深度绑定，优化路径成熟但扩展性受限
- **TVM**：Apache 开源，支持多硬件后端（CPU/GPU/FPGA/NPU），灵活性最强但上手门槛高
- **Triton**：OpenAI 推出，Python 语法写 GPU kernel，编译到 MLIR，LLM 推理优化应用广泛
- 三条路线在 MLIR 上趋同，竞争焦点转向跨硬件可移植性与调试体验

## ML-Triton 多级编译（Intel, 2026-06）
整理自 [[inbox/2026-06-22-ML-Triton多级编译扩展]]
- 扩展 Triton 为多级 lowering：workgroup → warp → intrinsic，对齐 GPU 硬件层次
- 现有 Triton 直接从 workgroup 降到 per-thread，缺中间层级表达力
- 支持用户编译器 hint，面向 GEMM/MHA 密集算子；比 CUDA/SYCL 更可移植
- 与上方 MLIR Auto-Tuning 路线呼应，均走「MLIR + 自动调优」共识

## Apache TVM 发布 TIRx（2026-06-29 归档）
整理自 [[inbox/2026-06-29-编译器-TVM发布TIRx]]
- 2026 年 6 月 Apache TVM 发布 TIRx：硬件原生 DSL + 极简编译器栈，专为前沿 ML kernel 设计
- storage-first 设计：显式控制内存布局和线程分配，编译目标覆盖 GPU 和专用 AI 加速器
- 三大开发范式：专家手写 kernel、AI Agent 生成 kernel、megakernel 系统
- 设计哲学：随硬件代际演进持续适配，避免被特定架构锁定；性能已超越 cuBLAS
- 与 TileLang/Nautilus 形成三角：TIRx（硬件原生）、TileLang（tile 级自动调度）、Nautilus（纯代数自动生成）
- 补充（2026-08-18 归档，整理自 [[inbox/2026-08-14-AI编译器-TIRx]]）：Python 内嵌 DSL（`@T.jit`/`@T.prim_func`）；核库含 GEMM/attention/低精度算子（Blackwell）；设计借鉴 NumPy/CuTe/Triton/ThunderKittens/TileLang；已集成 FlashInfer、FlashAttention sm100（CuTeDSL）、cuBLASLt NVFP4 参考实现
- 补充（2026-08-26 归档，整理自 [[inbox/2026-08-22-AI编译器-TIRx硬件原生内核DSL]]）：抽象边界低于 TileLang/Triton——编排（流水线/同步/内存布局）留在源码，可复用 tile 原语交给编译器分派；三大要素为 execution scope（线程/warpgroup 粒度）、storage-first 布局（Shard/Replica/Offset）、tile primitive dispatch（TMA/ldmatrix/WGMMA/tcgen05 自动选型）；新硬件先以 intrinsic 进入、稳定后提升为 tile primitive；已随 TVM 0.25 发布 PyPI wheel + tirx-kernels（GEMM/attention）+ CMU MLSys 课程，并与 TileLang 社区合作作为其新底层
