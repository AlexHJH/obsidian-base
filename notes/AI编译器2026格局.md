## MLIR Auto-Tuning（EuroLLVM 2026, MLIR Workshop）
Intel 在第7届 MLIR Workshop 展示面向 Battlemage GPU 的端到端 auto-tuning：
- Linalg → LLVM IR 的 auto-tuning 框架，用 tuneable "knob" ops 编码优化空间自动搜索最优 tiling
- 无需用户手动指定 tiling，上游 MLIR 即可达 SOTA 框架的 kernel 性能
- ASTER：基于 MLIR 的汇编工具链；Roofline 开源 mlir-track-src 追踪 pass pipeline 中的操作变换
- 关联 [[inbox/2026-06-19-Triton跨厂商基准与形式化验证]]（编译器验证方向）

## Triton 登陆 Blackwell
NVIDIA 与 OpenAI 合作使 Triton 编译器全面支持 Blackwell 架构，自动利用新 Tensor Core 和 MXFP8/MXFP4 微缩放格式。标志着 Python-first GPU 编程在最新硬件上成熟，FP8 GEMM 无需手写 CUDA 即可获显著加速。

## Hexagon-MLIR: 高通开源
Qualcomm 基于 MLIR 构建 Hexagon-MLIR 开源编译栈，打通「写 Triton → 跑在手机 NPU」路径。结构化编译流程：图优化 → 算子级 lowering → 代码生成，降低移动端 AI 部署门槛。

## Triton 跨厂商基准 + 内核形式化验证
整理自 [[inbox/2026-06-19-Triton跨厂商基准与形式化验证]]
- **Red Hat 跨厂商基准**：四种路线横评（手写 Triton / 自动生成 / 各厂商后端），强调可复现性与跨 vendor 可移植性；Helion tile-first DSL 在可付调优成本下峰值最优
- **Triton 2.0 后端重写为 MLIR**：手写与自动生成 kernel 性能差距持续缩小
- **指针安全形式化验证**：基于 Z3 SMT 静态证明内核无越界访问，瞄准集成进 Triton 编译流水线
- 趋势：竞争从「覆盖更多硬件」转向「生成代码更优 + 正确性可证明」；关联 [[推理引擎格局-vLLM-SGLang]]（Triton 已成 vLLM 注意力后端默认 kernel 层）

## 趋势判断
- Triton 从 NVIDIA 专属扩展到 Qualcomm NPU，MLIR 成为编译器基础设施共识
- Python-first kernel 编程从云端下沉到端侧，统一编程体验
- 编译器竞争从「谁支持更多硬件」转向「谁生成代码更优」

## TVM vs XLA vs Triton 三路线对比（Modular 系列）
整理自 [[inbox/2026-06-15-AI编译器TVM-XLA-Triton格局]]
- **XLA**：Google 主导，与 JAX/TF 深度绑定，优化路径成熟但扩展性受限
- **TVM**：Apache 开源，支持多硬件后端（CPU/GPU/FPGA/NPU），灵活性最强但上手门槛高
- **Triton**：OpenAI 推出，Python 语法写 GPU kernel，编译到 MLIR，LLM 推理优化应用广泛
- 三条路线在 MLIR 上趋同，竞争焦点转向跨硬件可移植性与调试体验
