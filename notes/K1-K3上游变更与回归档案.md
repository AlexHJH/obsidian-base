# K1/K3 上游变更与回归档案

每条记录要回答：影响哪个后端、最小复现是什么、哪一级验证通过、还有什么没测。区分公开源码与组织内部材料；未获授权的日志、路径、客户样本和性能数字不进入同步仓库。

## 优先跟踪

| 方向 | 记录口径 |
|---|---|
| RVV／IME／量化内核 | Q4_0/Q4_1 的 256 特化和派发边界、未对齐 fallback、K1 与 K3 指令集差异、编译器 flags；对照通用 CPU 输出和真机性能 |
| MTP／状态回滚 | 同 prompt 开/关 MTP 逐 token 校验；分开记录 draft、验证、回滚、提交数及接受率；覆盖语言和 prompt 类型，不把单样例归因到语言 |
| Triton／TLE | `smt_rvisa` tile lowering、ABI 和布局兼容、编译产物与 cache key；对照紧凑尾块和含 padding 的边界测试 |

## 2026-11-28｜验证批次与回滚分开定位

- [SpacemiT #78 作者验证](https://github.com/spacemit-com/llama.cpp/pull/78#k3-revalidation-after-the-q8-moe-fix-2026-11-26)：K3 `ba45b49`、PR head `4f3ba79`，Qwen3.6-35B-A3B-MTP UD-IQ2_XXS 的 draft-3 对比关闭推测，中文在生成第 26 token 偏离，英文在第 116 token 偏离；普通 EOS 和忽略 EOS 都在相同位置偏离，样例均到 128-token cap。已测 draft-2 一致；12-token smoke 不覆盖。另一个模型 Qwen3.5-0.8B Q8_0 的 144/144 一致与 3/8 提速属于单独样本，不证明 35B 没问题，也不能按语言泛化。#74 仍是独立前置；本笔记未跑板，也未归因给 #78。
- 先冻结第一个不同 token 之前的逻辑前缀，用 fresh serial 对真实 verifier batch：对齐 mask、位置、草稿锚点、后端派发与量化，记录目标 top-1/top-2 logits 和 margin。如果 verifier 已偏，再定位层或算子，用 [llama.cpp 对照方法](https://github.com/ggml-org/llama.cpp/issues/28111)逐列和批量比较。只有前向一致才缩到拒绝后状态：同一快照、拒绝位置和 logical token index，对比 clean replay，并加入 reorder、slot reuse、padding、不同 accepted lengths。[SGLang KDA 对照](https://github.com/sgl-project/sglang/pull/33722)是测试设计参考，不是 SpacemiT GDN 结论。再用同权重 generic CPU 与较早可比构建交叉验证。
- [上游 #31669](https://github.com/ggml-org/llama.cpp/pull/31669)改了 recurrent replay；[SYCL #33121](https://github.com/ggml-org/llama.cpp/issues/33121)报告独立回归。同步时需要核实实际 GDN 放置、记录有无 replay 输入并扩充 heterogeneous accepted-length 测试，不能把另一路径的退化当 K3 根因。

### 构建可复现性

[spine-triton README](https://raw.githubusercontent.com/spacemit-com/spine-triton/main/README.md)中 0.8.1 RISC-V 资产为连字符命名，正式 [0.8.1 资产列表](https://github.com/spacemit-com/spine-mlir/releases/expanded_assets/0.8.1)为 `spine-mlir.riscv64.0.8.1.tar.gz`，发布页 SHA-256 `4016e04d3dc3073c90a2bfcf97b90cd98ab9534a514f5aab6718f6c67c70fdf9`（公布值，未重新下载验哈希）。[FlagTree #1381](https://github.com/flagos-ai/FlagTree/pull/1381/files)所用 RISC-V CPython 3.12–3.14 与 MLIR bindings 已有同名发布资产；x86/QEMU CI 的 0.8.0 pin 是另一条路径。资产可见不等于 wheel、ABI、方言和板测已通过。先用固定 hash 与两条 raw-mv suite 做干净构建，再分开记录 QEMU 与真机结果。
