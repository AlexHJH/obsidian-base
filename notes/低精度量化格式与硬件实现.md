# 低精度量化格式与硬件实现

重点：MXFP4、实验性 MXINT4、NVFP4。对比 FP16 输入的缩放与编码、低精度乘加和反量化，以及从 PTQ 到 QAT 的精度和工程代价。

- 规格：分别记录元素编码、组大小、尺度编码、是否有全局尺度、舍入与饱和。OCP MX v1.0 包含 MXFP4 与 MXINT8；不能把泛称 MXINT4 的实现标成 OCP MX v1.0 规定格式。遇到 MXINT4，逐篇记录各自的定义。
- 硬件：分开估算块最大值归约、尺度生成、归一及舍入、打包、矩阵读取／解码、乘积和累加。用综合结果或板测确认面积、功耗、吞吐；别用位宽直接推代价。
- 软件：把权重-only 和 W4A4 分开，记 group size、精度敏感的跳过层及真正派发的 kernel。硬件能力和运行时派发分别验证。
- 精度：固定模型与校准集，比较直接量化、校准 PTQ 和 QAT；分别记录中英文、长上下文和实际任务。不要从某种格式名直接推断一定需要 QAT。

一手入口：[OCP MX v1.0](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1.0-spec-final-pdf/)、[CUTLASS](https://github.com/NVIDIA/cutlass)、[MLX](https://github.com/ml-explore/mlx)、[AMD Quark](https://quark.docs.amd.com/)。模型量化配置、发布方评测、内核源码和设备测量分别存证。

## 2026-11-28｜FP16→MXFP4：换 scale 规则不必换 GEMM

[Midmax 预印本 §§3、4.4](https://arxiv.org/pdf/2611.32873)在原有 32 元素 E2M1 + E8M0 格式里，只改**权重**块 scale。设正常有限 FP16 块最大绝对值为 m×2^e（1≤m<2）；[OCP MX v1.0 §6.3](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf)的基线 scale 是 2^(e−2)。Midmax 在 m≥1.75 时把它翻倍。普通 FP16 绝对值只需检查 fraction 最高两位均为 1，再有条件地把 E8M0 指数加 1。

| 输入 FP16 amax（十六进制） | floor：scale；反量化 | Midmax：scale；反量化 |
| --- | --- | --- |
| 6.99609375（0x46ff） | 1；(6, 0.5) | 1；(6, 0.5) |
| 7.0（0x4700） | 1；(6, 0.5) | 2；(8, 0) |
| 7.00390625（0x4701） | 1；(6, 0.5) | 2；(8, 0) |

每块第二个输入 0.5（0x3800），其余 30 个 +0。按 E2M1 就近偶数与饱和做标量复核：E8M0 scale 字节为 127/128；表中 (6, 0.5) 和 (8, 0) 的逻辑元素码分别为 (7,1) 和 (6,0)，不规定 packed byte 顺序。刚超过门槛时最大值重构更准，但小值可能被压成 0。实现还需测试带符号、全零、FP16 非正规数和非有限值。

- **离线权重**：改 packer 即可，已有 E2M1 GEMM 不变。**在线激活**：两位判定是增量逻辑，完整成本还含 amax 归约、缓冲、逐 lane 舍入/饱和及打包，不能把位判断等同于面积或时序。对比实验性 MXINT4 时须先钉住 INT4 编码范围和比例；OCP v1.0 表 1 没有 MXINT4。
- 六个 1B–8B 模型的 A4W4 实验中，Midmax 对 floor 平均 +0.12 个百分点，67% 配置改善；GPTQ 与 block rotation 平均影响更大。激活仍用 Stats。这个 PTQ 结果没有测在线转换、K3、PPA 或 MoE 迁移，也不能推出一律不需要 QAT。

### Export 对照：逻辑码、反量化值与 kernel 分开

[NVIDIA ModelOpt changelog](https://github.com/NVIDIA/Model-Optimizer/blob/main/CHANGELOG.rst)记录了 NVFP4 fake quant 与 HF/ONNX 真导出在 E2M1 tie 上的归一化对齐；验证时固定 exporter commit，逐块比码而不只比误差均值。[DeepSeek V4/V4.1 的 NVIDIA 转换](https://github.com/NVIDIA/Model-Optimizer/blob/main/examples/deepseek/README.md#lossless-mxfp4--nvfp4-weight-cast---cast_mxfp4_to_nvfp4)在 E4M3 尺度相对 tensor scale 可精确表示时，可保留路由专家的 E2M1 nibble，越界块另走 fallback，激活仍独立校准。32 个元素的理想块存储由 17 B 变为 18 B（未计额外尺度、padding 与对齐）。先统计精确块比例并比较反量化权重，再对照 logits 与 runtime，不能把局部权重等价当成整模型等价。
